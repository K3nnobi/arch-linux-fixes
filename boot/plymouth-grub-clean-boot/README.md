# Plymouth + GRUB Clean Boot

Configures the standard Plymouth `spinner` theme for a quieter graphical boot and removes the two GRUB status messages that can appear immediately before Plymouth:

```text
Loading Linux ...
Loading initial ramdisk ...
```

## Status

**Manually tested and validated after a real reboot** on the original setup:

- Arch Linux
- GNOME / GDM
- Wayland
- GRUB
- `linux-lts`
- NVIDIA
- traditional `mkinitcpio` hooks using `udev`

Validated result:

- Plymouth installed;
- `spinner` theme active;
- `plymouth` hook immediately after `udev`;
- `quiet splash` enabled;
- initramfs rebuilt successfully;
- GRUB configuration regenerated successfully;
- `Loading Linux ...` hidden;
- `Loading initial ramdisk ...` hidden;
- Plymouth spinner displayed during boot.

## Danger / read this first

**This is a boot-path configuration. A bad edit to `mkinitcpio`, GRUB or initramfs can make the system fail to boot.**

For that reason, this repository currently publishes the **confirmed manual procedure only**, not a one-command installer.

Do not apply this guide blindly to:

- systemd-boot;
- dracut;
- `mkinitcpio` configurations using the `systemd` hook instead of the traditional `udev` layout;
- a GRUB `10_linux` file whose relevant structure does not match the documented case.

Keep an Arch installation USB available when modifying boot files.

## Files involved

Before changing anything, back up:

```text
/etc/plymouth/plymouthd.conf
/etc/mkinitcpio.conf
/etc/default/grub
/etc/grub.d/10_linux
```

Example:

```bash
sudo cp -a /etc/plymouth/plymouthd.conf /etc/plymouth/plymouthd.conf.before-clean-boot
sudo cp -a /etc/mkinitcpio.conf /etc/mkinitcpio.conf.before-clean-boot
sudo cp -a /etc/default/grub /etc/default/grub.before-clean-boot
sudo cp -a /etc/grub.d/10_linux /etc/grub.d/10_linux.before-clean-boot
```

## 1. Install Plymouth

```bash
sudo pacman -S --needed plymouth
```

Set the standard spinner theme in `/etc/plymouth/plymouthd.conf`:

```ini
[Daemon]
Theme=spinner
```

If the file already contains other settings, preserve them. Change only the theme key that is required.

## 2. Add the Plymouth mkinitcpio hook

This confirmed setup used the traditional `udev` hook layout.

The important rule is:

```text
udev plymouth
```

with `plymouth` **immediately after `udev`** and present only once.

The tested configuration was:

```bash
HOOKS=(base udev plymouth autodetect microcode modconf kms keyboard keymap consolefont block filesystems fsck)
```

Your system may contain additional hooks. Preserve them and their required ordering; do not replace the whole line just because it differs from this example.

## 3. Add `quiet splash` to GRUB

Edit `/etc/default/grub` and ensure that both parameters exist in:

```text
GRUB_CMDLINE_LINUX_DEFAULT
```

Add only missing parameters. Preserve existing kernel, NVIDIA, filesystem and other command-line options.

Example concept:

```text
GRUB_CMDLINE_LINUX_DEFAULT="... quiet splash ..."
```

Do not duplicate `quiet` or `splash`.

## 4. Hide GRUB's Linux/initramfs text

The two messages are generated by GRUB, not Plymouth.

Do **not** permanently edit:

```text
/boot/grub/grub.cfg
```

That file is generated and will be replaced by `grub-mkconfig`.

The confirmed fix was applied to:

```text
/etc/grub.d/10_linux
```

Inside that generator, identify the output statements associated specifically with the messages for:

```text
Loading Linux ...
Loading initial ramdisk ...
```

In the tested file they were the corresponding generated `echo` statements equivalent to:

```bash
echo '$(echo "$message" | grub_quote)'
```

Comment/suppress **only those two text-output statements**.

### Critical warning

Do **not** remove or comment commands that actually load the kernel or initramfs, including the generated `linux`/`linuxefi` and `initrd`/`initrdefi` commands.

If the relationship between the message assignment and its `echo` is not clear in your current `/etc/grub.d/10_linux`, stop instead of guessing.

## 5. Rebuild initramfs

```bash
sudo mkinitcpio -P
```

**Do not interrupt this command.**

If it reports an error, fix or restore the configuration before rebooting.

## 6. Regenerate GRUB

```bash
sudo grub-mkconfig -o /boot/grub/grub.cfg
```

**Do not interrupt this command.**

Read its output and resolve errors before rebooting.

## 7. Reboot and validate

After a successful rebuild:

```bash
sudo reboot
```

Expected visual flow:

```text
GRUB
  ↓
Plymouth spinner
  ↓
GDM / GNOME
```

without the two intermediate `Loading ...` lines.

## Verification before reboot

Check the Plymouth hook:

```bash
grep '^HOOKS=' /etc/mkinitcpio.conf
```

Check kernel parameters:

```bash
grep '^GRUB_CMDLINE_LINUX_DEFAULT=' /etc/default/grub
```

Check the theme:

```bash
grep -E '^[[:space:]]*Theme=' /etc/plymouth/plymouthd.conf
```

Then make sure both rebuild commands completed with no errors.

## Rollback

Restore the four files from the backups created before the change:

```bash
sudo cp -a /etc/plymouth/plymouthd.conf.before-clean-boot /etc/plymouth/plymouthd.conf
sudo cp -a /etc/mkinitcpio.conf.before-clean-boot /etc/mkinitcpio.conf
sudo cp -a /etc/default/grub.before-clean-boot /etc/default/grub
sudo cp -a /etc/grub.d/10_linux.before-clean-boot /etc/grub.d/10_linux
```

Then rebuild both generated outputs again:

```bash
sudo mkinitcpio -P
sudo grub-mkconfig -o /boot/grub/grub.cfg
```

Do not reboot if either rebuild reports errors.

## Updates

A GRUB package update can replace `/etc/grub.d/10_linux` and make the two messages return. Never restore an old `10_linux` backup on top of a newer package version just to hide the text; re-check the new generator and reapply the visual-only change to its current structure.

Likewise, do not restore an old full boot configuration blindly after major bootloader or initramfs changes.

## Why there is no `fix.sh` yet

The original visual result is confirmed, and an ArchMind implementation was designed with backups, validation and automatic rollback on rebuild failure. However, this public repository will not ship a generic boot-changing script until the current GRUB/mkinitcpio variants have been reviewed sufficiently for a safe standalone implementation.

For boot configuration, refusing unsafe automation is better than offering a convenient script that can leave another user's system unbootable.
